Microsoft Reports Agentic AI Framework Scanning GitHub for Exposed Secrets and Abusing Azure Key Vault

Date: 2026-11-06
Tags: llmjacking, malicious-tool

Executive Summary

Microsoft Threat Intelligence observed threat actors using an agentic AI offensive framework, ARTEX, to scan public GitHub repositories for exposed secrets and advance from discovery to Azure Key Vault data exfiltration in about five minutes. The same campaign used valid leaked or stolen application credentials for service principal sign ins across dozens of Microsoft Entra ID tenants beginning October 28, 2026, and abused compromised Azure AI services. Defenders should rotate exposed application credentials, audit service principal sign ins from the listed IP addresses, and monitor Azure Key Vault and Storage Account access.

Detailed Findings

According to microsoft.com, Microsoft Threat Intelligence observed threat actors using an agentic AI offensive framework, ARTEX, to search public GitHub repositories for exposed secrets including credentials, application credentials, and AI inference related API keys across multiple applications and cloud services. Microsoft reported that in at least one case an AI agent advanced from scanning GitHub for secrets to exfiltrating data from Azure Key Vault in just five minutes. According to microsoft.com, as early as October 28, 2026, Microsoft began observing successful service principal sign ins from IP address 199.19.77[.]84 involving multiple application IDs, including cases where a multitenant application credential was compromised at the source and used to access multiple downstream tenants. The threat actor used the compromised credentials for cloud resource discovery and for credential and data exfiltration from Azure Key Vaults and Storage Accounts, and for abuse of Azure AI services. Microsoft also reported reconnaissance from 157.22.126[.]128 targeting AI workloads deployed on Azure AI services, and malicious operations from 65.87.223[.]26 that included embedded shell commands in a user agent and attempts to obtain App Service authentication tokens; the same IPs were reported by Todyl in a similar campaign. The compromised applications accessed SharePoint and OneDrive in targeted tenants, including file downloads and mailbox item access, and the actor enumerated subscriptions, resource groups, permissions, AI model deployments, and service configurations in Azure.

Detection Recommendations

Audit Microsoft Entra ID service principal sign in logs for the listed IP addresses and for anomalous multitenant application access, and rotate any application credentials or secrets that were ever committed to public repositories or vendor owned multitenant applications. Enable Defender for Cloud AI threat protection to detect validation and abuse of stolen Azure AI resources, monitor Azure Key Vault and Storage Account read operations that return credentials and connection strings, and alert on App Service authentication token requests. Review Microsoft Graph API search activity for content enumeration across SharePoint and OneDrive.
