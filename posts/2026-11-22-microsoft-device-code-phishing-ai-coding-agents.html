Microsoft Security Documents Device Code Phishing That Can Steer AI Coding Agents Remotely

Date: 2026-11-22
Tags: phishing

Executive Summary

Microsoft Security showed in a lab simulation that a phished OAuth device code authorization for an AI coding agent can let an attacker steer an active GitHub Copilot CLI session, run commands on the victim machine, poison agent memory, read cloud synced sessions, and reach private repositories. The technique is not specific to GitHub and works against any public client that supports the device flow, with the attacker choosing the requested scopes. Defenders should restrict device code flow for agent clients, require conditional access, and alert on device code sign ins for coding agents.

Detailed Findings

Microsoft Security used GitHub Copilot CLI as an illustrative example in a controlled lab simulation, according to microsoft.com. Copilot CLI can work with code, run commands on a user machine, retain context across sessions, and allow an active session to be steered remotely, and like many command line tools it supports the OAuth device flow for sign in. Microsoft said the phishing technique is not specific to GitHub or Copilot CLI: any public client that supports the device flow can be abused the same way, and the attacker chooses the requested scopes when starting the flow. In the simulation a victim test account approved a GitHub device code request initiated by an attacker controlled client. Microsoft reported four outcomes: steering an active Copilot CLI session remotely when the user enabled remote control and organization policy allows it, and subject to local permissions and approval settings, having the agent run commands on the user machine; adding misleading entries to the agent memory that could influence later interactions; reading Copilot CLI sessions synchronized to the cloud; and accessing private repositories available to the affected account. Microsoft stated these are proof of concept results showing existing features working as designed could be abused after a phished authorization, and that they are not attacks observed in the wild. Each outcome requires the victim to approve a device code request initiated by the attacker and depends on account permissions and enabled features.

Detection Recommendations

Restrict or disable OAuth device code flow for AI coding agents and other public clients where possible, and require conditional access and number matching. Alert on device code sign ins, especially approvals from new locations or for broad scopes, and on agent sessions that begin invoking shell or file tools shortly after authentication. Review agent memory and cloud synced session logs for injected entries. Enforce least privilege on repositories and cloud resources reachable by the agent account.
